TMMS is a geographic, asset-centric operations platform for high-voltage transmission networks. It keeps one authoritative record of every asset and location, and drives each piece of work through a closed loop: Plan → Dispatch → Execute → Document → Verify.

Why TMMS

One closed loop
from plan to proof

Utilities rarely fail for lack of work orders. They fail because the plan, the dispatch, the field evidence and the verification live in separate places — so nobody can prove what happened, where, or when. TMMS closes that loop in a single georeferenced system.

1

Georeferenced by default

Every substation, line, tower and asset carries coordinates. Locations are verified, not trusted.

2

Accountable to the person

Each stage has one owner. The verifier can never be the executor, and every action is logged.

3

Nothing disappears

Recurring work is automated, evidence is retained, and closed work feeds the next plan.

Built for the field, trusted by the board

A crew sees only its assigned work. A manager sees the crews it commands. A director sees the region. An executive sees the whole network — the same data, filtered by role, never duplicated.

TMMS Product Brochure09
Under the hood

Modern, secure and built to stay consistent

A React single-page console talks to a role-scoped Node / Express API over one authoritative SQLite datastore. Schema changes are idempotent, referential integrity is enforced, and every mutation is written to an audit log — with a redacted, size-capped request body.

Role-scoped reads

Queries are filtered by region and department, so a manager only ever sees its own domain.

Referential integrity

Cascades are transactional and leave foreign_key_check empty.

Auditable by design

Sessions expire, expired sessions are pruned, and sensitive fields are redacted.
