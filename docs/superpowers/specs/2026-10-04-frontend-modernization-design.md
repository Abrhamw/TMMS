# Frontend Modernization - Design

Date: 2026-10-04
Status: Approved (design), pending implementation plan

## 1. Summary

The TMMS frontend is a hand-rolled React single-page app with plain CSS, unicode
glyph icons, no motion, no theming, and navigation that mostly replaces the whole
page. It functions, but it does not guide an executive or a field worker through the
data with confidence, and it does not feel like a modern product.

This design modernizes the frontend incrementally. A new styling and interaction
foundation is introduced alongside the existing stylesheet, then applied first to the
two personas that matter most - executives and field workers - before rolling out to
the rest of the application. No existing capability is removed, and unmigrated pages
keep working unchanged throughout.

The guiding sentence: guide every role to the deepest useful level, with clarity and
motion, without overwhelming them.

## 2. Goals

- Establish a modern design foundation: Tailwind v4 theme bound to the TMMS brand
  tokens, a real type scale, `lucide-react` icons, `motion` interactions, and a
  light/dark theme.
- Replace full-page jumps with progressive drill-down: contextual side drawers that
  reveal the detail behind a KPI, chart segment, map feature, or list row.
- Make the executive briefing interactive: KPI and chart drill-down, animated
  counters, hover detail, live refresh.
- Make the worker experience mobile-first: large touch targets, an animated
  step-by-step task runner, drawer-based photo/GPS/capture, and a clear sync state.
- Upgrade the shared visualization primitives with hover/tap detail and draw-in
  animation while staying dependency-light.
- Keep the change low risk: additive stack, no preflight reset, existing pages intact
  until deliberately migrated.

## 3. Non-goals

- No backend or API change. All data comes from existing endpoints.
- No big-bang rewrite. Migration is phased; the app must build and run after every
  phase.
- No new data model and no removal of records or pages.
- No accessibility compromise: motion respects `prefers-reduced-motion`; contrast and
  focus states are preserved.

## 4. Stack and coexistence

- `tailwindcss` v4 with `@tailwindcss/vite`. Tailwind is imported as theme and
  utilities layers only (`@import "tailwindcss/theme.css"` and
  `@import "tailwindcss/utilities.css"`); Tailwind preflight is deliberately omitted so
  the existing `styles.css` base is untouched.
- `motion` (React) for animation, `lucide-react` for icons, and
  `clsx` + `tailwind-merge` + `class-variance-authority` for the UI kit.
- A vendored shadcn-style kit lives in `src/ui/` (Button, Card, Badge, Sheet/Drawer,
  Dialog, Tooltip, Tabs, Skeleton, Command palette) built on those primitives. The
  components are vendored rather than generated by the shadcn CLI so preflight
  assumptions and global resets are avoided.
- Because Tailwind utilities are in a layer and the legacy stylesheet is unlayered,
  legacy rules keep priority; new surfaces avoid legacy class names so there is no
  conflict. Migrated pages are reimplemented with the new kit and Tailwind utilities.

## 5. Foundation

- Theme tokens: brand green `#14532d`, deep green, teal, indigo accent, severity
  colors, chart palette, plus a dark palette, exposed as Tailwind theme values and as
  CSS variables usable by legacy code.
- Inter loaded via the document head; a consistent type and spacing scale.
- Motion conventions: route fade/slide, staggered card reveal, hover/press
  micro-interactions, animated counters, and chart draw-in. All gated by
  `prefers-reduced-motion`.
- `lucide-react` icons replace the unicode glyphs in navigation and new surfaces.
- Theme switch: `.dark` class on `<html>`, persisted per device, toggled from the top
  bar. New surfaces are fully themed in both modes; legacy surfaces receive a
  token-based dark pass in the rollout phase.

## 6. Shell, navigation, and guidance

- Top bar gains the theme toggle and, for permitted roles, a command palette trigger.
- Command palette (Ctrl/Cmd+K) for fast navigation to areas, records, and actions,
  reusing the existing search endpoint where appropriate.
- Breadcrumbs on every page; active-area highlighting; a consistent "back to
  briefing" affordance.
- A drawer/sheet system so drill-down opens beside the current view; deep-linking to a
  record still uses the existing routes and guards.

## 7. Executive command center

- The briefing becomes interactive. Each KPI and chart segment can be activated to
  open a drawer with its breakdown (for example, Critical condition -> the list of
  critical assets; overdue -> the overdue work list).
- Executive drawers present aggregate and exception detail (counts, trend, and top
  rows). They do not reintroduce the operational registers the executive was
  restricted from; where a fuller record exists on a permitted surface, a link is
  offered. Managers and workers receive record-level drawers on their surfaces.
- Counters animate on load; charts show hover detail; the briefing can live-refresh.

## 8. Worker field experience

- Mobile-first layouts with large touch targets and thumb-reachable actions.
- An animated step-by-step task runner: a progress stepper, clear current step, and
  validation cues.
- Capture flows (photos, GPS, readings) presented in bottom sheets rather than full
  page navigations, with optimistic feedback.
- A persistent sync/offline indicator so a worker always knows whether work is saved.

## 9. Data visualization upgrade

- The existing SVG primitives gain hover/tap detail, animated draw-in, animated
  counters, and consistent tooltips, remaining dependency-light.
- Charts stay accessible (labels, roles) and responsive across desktop, tablet, and
  mobile.

## 10. Phasing

- P0 Foundation: stack + theme + dark shell; app visually unchanged; build green.
- P1 Shell and kit: UI kit, navigation, drawers, icons, command palette.
- P2 Executive: interactive briefing redesign.
- P3 Worker: field experience redesign.
- P4 Rollout: apply the kit app-wide and complete dark theming and viz upgrade.

## 11. Verification

- `npm run build` succeeds after every phase.
- Headless Playwright screenshots at desktop (1440x900), tablet (1024x768), and mobile
  (390x844) for migrated surfaces; assert zero console errors and no layout
  regressions on unmigrated pages.
- Keyboard and reduced-motion checks on new interactive surfaces.
